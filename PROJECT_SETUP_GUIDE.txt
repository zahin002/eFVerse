PROJECT SETUP GUIDE (Local PostgreSQL)

Follow the steps below to run eFVerse (FHUB) fully locally.

--------------------------------------------------
PREREQUISITES

- Node.js v16+ and npm
- PostgreSQL 13+ installed locally, with `psql` available on your PATH
- A DB client is optional but helpful: pgAdmin, DBeaver, TablePlus, or
  the VS Code PostgreSQL extension all work fine alongside psql.

--------------------------------------------------
1. CREATE THE LOCAL DATABASE

Open a terminal and log into Postgres with your superuser (usually
"postgres"):

    psql -U postgres

Then create a dedicated database for the project:

    CREATE DATABASE fhub_db;
    \q

--------------------------------------------------
2. LOAD THE SCHEMA AND SQL LOGIC

Run the following files, in this exact order, against fhub_db.
(schema.txt must go first; update_player_status.txt must go last
because it calls a function defined in market_value_updater.txt.
The rest can run in any order between those two.)

    cd "SQL CODES"

    psql -U postgres -d fhub_db -f "schema.txt"
    psql -U postgres -d fhub_db -f "auto_stats_calc.txt"
    psql -U postgres -d fhub_db -f "booster_limit_trigger.txt"
    psql -U postgres -d fhub_db -f "default_form_trigger.txt"
    psql -U postgres -d fhub_db -f "delete_player_audit.txt"
    psql -U postgres -d fhub_db -f "effective_rating.txt"
    psql -U postgres -d fhub_db -f "logical_stats_enforcing.txt"
    psql -U postgres -d fhub_db -f "manager_audit.txt"
    psql -U postgres -d fhub_db -f "manager_insert.txt"
    psql -U postgres -d fhub_db -f "market_value_updater.txt"
    psql -U postgres -d fhub_db -f "player_build_save.txt"
    psql -U postgres -d fhub_db -f "player_card_stats insertion.txt"
    psql -U postgres -d fhub_db -f "similar_player_card.txt"
    psql -U postgres -d fhub_db -f "smart_search.txt"
    psql -U postgres -d fhub_db -f "train_card.txt"
    psql -U postgres -d fhub_db -f "update_player_status.txt"

You'll see a handful of harmless empty result sets scroll by — the
files contain a few leftover debugging `SELECT * FROM ...` lines from
development; they don't affect the schema.

Reference data (leagues, positions, stat types, form types, injury
types, training programs) is NOT included above — see Step 3.

--------------------------------------------------
3. SEED REQUIRED REFERENCE DATA

Several tables have no default rows but are required for the app to
function (Positions, StatType, FormType, InjuryType, TrainingProgram).
Insert at least the following before using the app — adjust/extend as
needed:

IMPORTANT: RoleGroup values are read by several stored procedures
(train_player_card_pro, calculate_suggested_stats, etc.) via
UPPER(pos.RoleGroup) checks against the literals FORWARD, WINGER,
MIDFIELDER, DEFENDER, and GOALKEEPER — use those exact values, not
abbreviations like "DEF"/"MID"/"FWD", or the CASE branches in those
functions will silently fall through to their ELSE/error case.

    INSERT INTO Positions (PositionCode, RoleGroup) VALUES
      ('GK','GOALKEEPER'),
      ('CB','DEFENDER'), ('LB','DEFENDER'), ('RB','DEFENDER'),
      ('DMF','MIDFIELDER'), ('CMF','MIDFIELDER'), ('AMF','MIDFIELDER'),
      ('LMF','MIDFIELDER'), ('RMF','MIDFIELDER'),
      ('LWF','WINGER'), ('RWF','WINGER'),
      ('SS','FORWARD'), ('CF','FORWARD');

NOTE: calculate_suggested_stats() (in auto_stats_calc.txt) only
handles FORWARD / MIDFIELDER / DEFENDER / GOALKEEPER — there's no
WINGER branch, so calling it for an LWF/RWF card returns an
{"error": "RoleGroup WINGER unknown"} JSON payload instead of stats.
This is a pre-existing gap in the SQL logic, not a setup mistake;
worth fixing in auto_stats_calc.txt if you rely on that feature.

    INSERT INTO FormType (FormName, Multiplier) VALUES
      ('A', 1.20), ('B', 1.05), ('C', 1.00), ('D', 0.90), ('E', 0.75);

    INSERT INTO InjuryType (InjuryName, DefaultMultiplier) VALUES
      ('Minor Knock', 0.90), ('Muscle Strain', 0.60), ('Serious Injury', 0.30);

    INSERT INTO TrainingProgram (ProgramName) VALUES
      ('Shooting'), ('Passing'), ('Dribbling'), ('Dexterity'),
      ('Lower Body'), ('Aerial'), ('Defending'),
      ('GK1'), ('GK2'), ('GK3');

    INSERT INTO StatType (StatName) VALUES
      ('OffensiveAwareness'), ('Finishing'), ('BallControl'), ('Dribbling'),
      ('Passing'), ('KickingPower'), ('Speed'), ('Acceleration'), ('Stamina'),
      ('Balance'), ('PhysicalContact'), ('Jump'), ('DefensiveAwareness'),
      ('Tackling'), ('Aggression'), ('GkAwareness'), ('GkCatching'),
      ('GkParrying'), ('GkReflexes'), ('GkReach');

You'll also want at least one League, Club, and Nationality row before
adding players via the Admin Panel.

--------------------------------------------------
4. CONFIGURE THE BACKEND ENVIRONMENT

    cd backend
    cp .env.example .env

Edit `.env` and set:
  - DATABASE_URL to match the database you created in Step 1
    (postgresql://<user>:<password>@localhost:5432/fhub_db)
  - DB_SSL=false (local Postgres doesn't use TLS by default)
  - JWT_SECRET to your own long random string
    (generate one with: openssl rand -base64 48)

Leave SUPABASE_URL / SUPABASE_KEY blank — they aren't used locally.

--------------------------------------------------
5. START THE BACKEND

    cd backend
    npm install
    node src/server.js

    (or, for auto-reload during development:)
    npx nodemon src/server.js

Confirm the console shows "Database URL Found" and
"Backend running on http://localhost:5001".

--------------------------------------------------
6. START THE FRONTEND

Open a NEW terminal:

    cd frontend
    npm install
    npm run dev

--------------------------------------------------
7. OPEN IN BROWSER

    http://localhost:5173/

Register a new account to get started. Both terminals (backend and
frontend) must stay running at the same time.

--------------------------------------------------
NOTES

- Run "npm install" again if you pull new dependencies.
- If the backend can't connect to Postgres, double-check DATABASE_URL
  (username/password/port) and that the Postgres service is running.
- If something stops working, restart both the server and the client.
